# بث Alpaca (SIP) — Algo Trader Plus

طبقة مستقلة (`alpaca_stream.py`) تستقبل الصفقات والأسعار وشموع الدقيقة لكل الأسهم الأمريكية من مصدر SIP عبر WebSocket.
لا تغيّر وظائف المنصة الحالية، ولا تحتوي أي كود لإرسال أوامر، وحساب التداول المسموح Paper فقط.

## الإعداد
1. انسخ `.env.example` إلى `.env` في مجلد المنصة وضع مفاتيح **Paper** من لوحة Alpaca.
   `.env` مستثنى من Git (`.gitignore`) ولا يُرفع.
2. `py -m pip install -r requirements.txt`
3. أوقف المنصة إن كانت تعمل، ثم: `py alpaca_check.py` (90 ثانية، أثناء الجلسة 4:00–20:00 نيويورك).
4. بعد نجاح الفحص: `ALPACA_STREAM=1` في `.env` ثم `py app.py`. الحالة: http://127.0.0.1:5000/api/alpaca/status

## حدود معروفة
- Alpaca يسمح غالبًا باتصال بث واحد: المنصة وأداة الفحص لا تعملان معًا (الخطأ 406).
- الأسعار (quotes) لكل السوق كثيفة جدًا. المعالجة قيست هنا بنحو 210 ألف رسالة/ثانية على خيط واحد، لكن سرعة
  الإنترنت وجهازك قد تكون الحد. إن ظهر 407 (slow client) اجعل `ALPACA_QUOTES` قائمة رموز أو `off`.
- التأخير المقاس = وقت الاستلام على جهازك − وقت الحدث في البورصة، فيتضمن فرق ساعة الجهاز (أداة الفحص تقيسه).
- البيانات متاحة عبر `alpaca_stream.latest_trade/latest_quote/minute_bars` و`/api/alpaca/status`؛
  لم تُربط بعد بحسابات الماسح والشارت (ربطها مرحلة لاحقة بموافقتك).
- يبدأ البث مع `py app.py` فقط (لا مع gunicorn/wsgi).

## الأخطاء
| الرمز | المعنى | سلوك المحرك |
|---|---|---|
| 402 | المفتاح أو السر خطأ | يتوقف ولا يعيد المحاولة |
| 409 | الاشتراك لا يشمل SIP | يتوقف، ولا يرجع إلى IEX |
| 406 | اتصال آخر مفتوح | ينتظر 60 ث ثم يعيد |
| 407 | جهازك أبطأ من البيانات | يعيد الاتصال؛ قلّل الرموز |
| انقطاع شبكة/خادم | — | إعادة اتصال بانتظار 1، 2، 4… حتى 60 ث |
| لا بيانات 30 ث أثناء التداول | اتصال معلق | إعادة اتصال |
